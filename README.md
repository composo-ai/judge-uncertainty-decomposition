# Decomposing LLM-Judge Uncertainty to Target Expert Labels

**Authors:** [Ryan Lail](https://github.com/ryanlail)<br>
**Affiliation:** [Composo AI](https://composo.ai)

An LLM judge evaluates outputs at scale, and human experts should label only where it is
least sure. The judge's natural escalation signal, the spread of its predicted label
distribution, conflates two uncertainties: **aleatoric**, real disagreement in the expert
pool, which more labels cannot reduce, and **epistemic**, the judge's ignorance of what the
experts would say, which even one label reduces. A small Bayesian model separates them: a
regression on the labels already collected learns how far to trust a black-box judge's
prediction on each item, and both components then follow as closed-form expressions, with
no sampling and no further judge calls.

- On a real LLM judge scored against exactly known truth (500 three-sided dice), the two
  estimated components isolate: estimated aleatoric tracks the true disagreement and not the
  judge's error, estimated epistemic tracks the judge's error and not the disagreement.
  The judge's own stated confidence is no guide to its actual error.
- On real human disagreement (ChaosNLI, 100 annotations per item), ranking by the epistemic
  estimate removes 83% more error than ranking by total uncertainty for the same expert
  labels, though simply escalating the least-labelled items does as well there.

**Paper:** *Decomposing LLM-Judge Uncertainty to Target Expert Labels*, submitted to the
NeurIPS 2026 workshops (4-page version). Preprint link to follow.

This repository holds everything needed to reproduce the paper: the synthetic dice testbed,
the ChaosNLI pipeline, both raw judge caches, the pre-registration documents, the gate
script that scored them, and the figures.

## Layout

| Path | What it is |
| --- | --- |
| `dice/` | Synthetic testbed. Generator, closed-form posterior quantities and the Dirichlet-multinomial concentration regression, ranking arms, sweeps S1-S6, the pre-registered gate, the misspecified-judge sweep (S7a), and the real-LLM-on-dice experiment (S7b). `RESULTS.md` is the registered results record. |
| `dice/caches/s7b_cache.jsonl` | Raw outputs of the real judge on the 500 dice (Experiment 1). Every S7b number in the paper derives from this file. |
| `dice/figures/` | The paper's figures, as generated by the scripts below. |
| `chaosnli/` | Real-data side. Data adapter, judge ensemble script, evaluation pipeline, registered analysis, `PREREG.md` (frozen before results were read) and `RESULTS.md` (the pre-registration scored). |
| `chaosnli/caches/judge_cache.jsonl` | Raw outputs of the judge on all 3,113 ChaosNLI items (Experiment 2): 12,452 rows, four prompt variants per item. |
| `chaosnli/embeddings_minilm.npz` | MiniLM item embeddings used for the familiarity features. `chaosnli/embed.py` regenerates it. |
| `chaosnli/registered_report.json` | Raw numbers behind `chaosnli/RESULTS.md`. |
| `docs/experiments_synthetic_dice.md` | Implementation spec for the dice testbed, including the day-0 changelog and the pre-registered S7 predictions. It refers to some planning documents that stay internal; the pre-registered content that the paper relies on is in this file, `chaosnli/PREREG.md`, and `dice/gate.py`. |

## Setup

Python 3.11 or later. No API keys are needed to reproduce the paper: both judge caches are
committed, and every analysis script reads from them.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m pytest        # 41 tests; the ChaosNLI-data tests skip until the data is present
```

### ChaosNLI data

ChaosNLI (Nie et al., 2020) is released under CC BY-NC 4.0, so its files are not vendored
here. Download `chaosNLI_v1.0.zip` from the [ChaosNLI repository](https://github.com/easonnie/ChaosNLI)
and unpack it so that `data/chaosNLI_v1.0/chaosNLI_snli.jsonl` and
`data/chaosNLI_v1.0/chaosNLI_mnli_m.jsonl` exist. The scripts and tests look there by default;
set `CHAOSNLI_DIR` to point elsewhere.

## Reproducing the paper

All commands run from the repository root.

### Experiment 1: dice with exactly known truth (`dice/`)

The registered simulation sweeps regenerate deterministically (registered seed counts are the
defaults; `--sweep smoke` is a fast check):

```bash
python -m dice.sweep --sweep s1 --out results/         # main curve
python -m dice.sweep --sweep s4 --out results/         # gate criterion C1
python -m dice.sweep --sweep s5track --out results/    # gate criterion C2
python -m dice.sweep --sweep s6dose --out results/     # dose-response
python -m dice.gate --results results/                 # scores the pre-registered exit criteria
python -m dice.s7a --out results/                      # misspecified-judge sweep
python -m dice.s7a --out results/ --ood-r 0.5
python -m dice.paper_figures --results results/ --out dice/figures   # Figures 1 and 2
```

The real-LLM results read the committed cache and need no API access:

```bash
python -m dice.s7b_analysis --cache dice/caches/s7b_cache.jsonl   # tier calibration, arms, diagnostic
python -m dice.s7b_replication --replicates 200                    # reveal-resampling CIs
python -m dice.isolation                                           # the isolation matrix (Table 1)
python -m dice.convergence_figure --replicates 200 --out dice/figures   # the hero figure
```

### Experiment 2: ChaosNLI (`chaosnli/`)

With the data downloaded as above, the registered analysis reproduces `chaosnli/RESULTS.md`
and `registered_report.json` from the committed judge cache:

```bash
python -m chaosnli.analysis --data-dir data/chaosNLI_v1.0 \
    --cache chaosnli/caches/judge_cache.jsonl --replicates 200 --procs 8 --out report.json
CHAOSNLI_DIR=data/chaosNLI_v1.0 python -m chaosnli.exploratory_paired_arms   # the per-arm paired table
```

### Re-querying the judge (optional, costs API calls)

Both judge scripts are cache-first and resumable: cached rows are never re-queried, so
running them against the committed caches makes no calls. To rebuild a cache from scratch,
delete or rename it and set the relevant keys (`AZURE_OPENAI_API_KEY` and
`AZURE_OPENAI_ENDPOINT`, or `OPENAI_API_KEY`, or `ANTHROPIC_API_KEY`). The paper's judge was
the Azure OpenAI deployment `gpt-5.6-terra`, queried 18 August 2026; `--dry-run` prints the
prompts without calling anything.

```bash
python -m dice.llm_judge --cache dice/caches/s7b_cache.jsonl --n-dice 500 --diagnostic
python -m chaosnli.judge --data-dir data/chaosNLI_v1.0 --cache chaosnli/caches/judge_cache.jsonl
```

## Pre-registration

The dice gate thresholds (`dice/gate.py`) and the ChaosNLI protocol and predictions
(`chaosnli/PREREG.md`) were committed before the corresponding results were read, and the
results files score them as written, refutations included. Where a registered prediction
missed, `chaosnli/RESULTS.md` says so and labels the later analysis as exploratory.
